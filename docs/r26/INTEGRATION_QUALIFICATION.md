## Deterministic real fault controls

Pre-admission cancellation, cancellation after an observed suspended pure reducer
generator step, and cancellation after publication preparation all require empty
cancelled receipts and no stored generation. The token uses read-only call-site/
generator-state inspection to record the actual phase witness. It does not modify
producer code, inject mathematical results or bypass artifact verification.

The coordinator specifically authorized a harness-owned sink subclass using the
existing internal `_commit_transaction` fault seam. This is qualification-only
fault simulation, not a public sink extension/callback API. All production SQL,
transactions, recovery, complete readback and cohort verification remain real.
The fixed controls raise before the real COMMIT (requiring complete rollback),
perform the real COMMIT then lose its acknowledgement (requiring verified recovery),
and set cancellation after actual COMMIT (requiring successful committed output
with cancellation observed). Identical retries and reopen readbacks must preserve
the complete original generation. These controls are not an OS process crash,
power-loss or filesystem durability proof.

A separate changed valid invocation under an existing run key must conflict and
preserve original bytes. Deliberate missing-result, damaged-generation metadata,
binding-payload and schema corruptions occur only in fresh owned synthetic DBs.
Each tampering connection explicitly uses DuckDB threads1 and closes before real
sink reopen/readback rejects the damage. No production sink SQL, feature math or
cohort verifier is monkeypatched.
